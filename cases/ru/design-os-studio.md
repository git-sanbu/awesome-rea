## Вопрос

Как читать и записывать контейнеры Figma .fig и заново реализовать поведение редактора в независимой настольной студии?

## Что сделал REA

Публичные спецификации проекта называют morluto/rea 6.7.0 (`npx -y rea-agents`) инструментом для обратной разработки полей Figma и фиксируют запуск analyze-javascript-application на извлечённом JavaScript редактора. Те же заметки сообщают, что пути wasm были недоступны (WABT и Ghidra не были установлены), поэтому схема kiwi была декодирована локальным читателем. В репозитории также есть вывод CLI rea, включая завершённые запуски inspect-macho и analyze-javascript-application и некоторые неудачные вызовы. README продукта не упоминает REA.

## Результаты, сообщенные автором

DESIGN:OS Studio — опубликованная настольная студия (проверена версия v0.7.11), которая читает контейнеры Figma .fig и записывает версию 106, локально заново реализует поведение редактора и поставляет stdio MCP-сервер на 39 инструментов и многоязычную генерацию кода. README сообщает о более чем 6 000 тестах macOS CI и тестах кругового пути designos-fig. Сопровождающий утверждает, что для этой работы по Figma использовался REA. Этот каталог просмотрел публичные спецификации, сохранённый вывод rea и README; студию не устанавливал и rea не запускал повторно.

## Ограничения и непроверенные претензии

README продукта не указывает REA. Некоторые записанные запуски rea завершились ошибкой (неизвестная команда или не настроенный поставщик нативного анализа). Полные черновики сессий, упомянутые в других заметках, хранятся вне репозитория. Известная проблема #834 остаётся открытой: при сохранении .fig теряется форматирование нумерованных списков, а унаследованные или привязанные к переменным заливки на экземплярах записываются как фиксированные значения. Лицензия — PolyForm Shield 1.0.0 (исходный код доступен, это не лицензия открытого ПО). Этот каталог не воспроизводил совместимость .fig самостоятельно и не запускал набор тестов повторно.

## Чему научиться

Документированное использование REA может быть в спецификациях проекта и в сохранённых свидетельствах CLI, даже если README продукта об этом молчит, а смешанный процесс всё же может требовать локального запасного пути, когда пути wasm у REA недоступны.
