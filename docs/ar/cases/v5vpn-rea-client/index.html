V5VPN: بحث البروتوكول لبوابة ذات نطاق محدد وعميل النفق

تمت ترجمة هذه الطبعة آليًا من النسخة الإنجليزية التحريرية. تبقى الاقتباسات الأصلية في لغتها المصدر. عندما تكون الصياغة غير واضحة، راجع اللغة الإنجليزية والمصادر المرتبطة. النسخة الانجليزية

الهدف: عميل LeadSec V5VPN 5.3.3.x وبروتوكول بوابة v2.0

المؤلف / الإسناد: hygkui

تاريخ مراجعة المصدر: 2026-10-21

حالة المراجعة: تمت مراجعة المصادر؛ لا يتم إعادة تشغيل اختبارات المؤلف بشكل مستقل.

السؤال

كيف يمكن للمصادقة واكتشاف الموارد وأبحاث الاتصال إبلاغ عميل مستقل محدد النطاق؟

ما فعله REA

يستشهد المؤلف صراحةً بـ morluto/rea كمرجع للهندسة العكسية ويوثق الرموز والتفكيك وتعيينات الذاكرة في SecUI.exe وSecController.dll وSecLogin.dll وSecSSL.dll وVpnServ.exe. يربط README المصادقة وفروع انتهاء صلاحية كلمة المرور واكتشاف الموارد واتصال HTTP بتنفيذ Go/MyGo المستقل؛ سجلات مكالمات REA الكاملة ليست عامة.

النتائج التي أبلغ عنها المؤلف

يتم توفير سطح المكتب العام Go/MyGo ومصدر CLI وملاحظات البروتوكول والاختبارات. أبلغ المؤلف عن اتصال شامل على جهاز تطوير Windows وبوابتي إنتاج، تغطي بوابة SSL VPN والموارد المعتمدة وأنفاق HTTP CONNECT.

القيود والمطالبات التي لم يتم التحقق منها

النطاق المبلغ عنه هو 5.3.3.x وتم تجميع بروتوكول v2.0. Linux/macOS ولكن لم يتم اختباره. لا يوجد محول افتراضي لـ kernel أو IPsec أو توجيه الشبكة بالكامل؛ مفتاح USB وتسجيل الدخول المجهول ومجموعات التشفير الصينية غير مدعومة. لم يتصل هذا الكتالوج بالبوابات أو يتحقق من الأمان ولا يتعامل مع الصياغة "المخترقة بالكامل" باعتبارها استنتاجًا ثابتًا.

ماذا نتعلم

نطاق بروتوكول منفصل عن اختبارات النظام الأساسي. تتطلب سهولة استخدام العميل التحقق من الصحة مقابل بوابات وسيناريوهات محددة.

دليل استخدام REA في المصدر

基于 REA (Reverse Engineer Anything) 逆向分析技术与 MyGo 跨平台桌面技术架构，重新实现的现代化 V5VPN 客户端。
